# status-page

The OK040 homepage (static, served by Web Station) with a live "System status" section. Not a container, but it reads container state, so it is documented as a project.

| Piece | Where on the NAS | In this repo |
|---|---|---|
| Homepage | `/volume1/web/index.html` | [`web/index.html`](web/index.html) |
| Icons | `/volume1/web/favicon.ico`, `favicon.svg`, `apple-touch-icon.png` (must be mode 644 or nginx returns 403) | [`web/`](web/) |
| Data collector | `/volume1/docker/status-page/gather-status.py` | [`gather-status.py`](gather-status.py) |
| Output | `/volume1/web/status.json`, regenerated by the task below, polled by the page every 5 minutes | not stored |
| Scheduler | DSM Task Scheduler task `status-page-refresh`, user `root`, runs `python3 /volume1/docker/status-page/gather-status.py` | see [host](../host/) |

The page shows seven signal groups. Status markers are green for `ok`, amber for `warn`, and gray outlined for `stale` or `unknown`. Time Machine freshness becomes stale after 7 days; LinkedIn backup freshness warns after 8 days and becomes stale after 9. The Hetzner backup becomes stale after 26 hours without a successful pull; a failed latest run is a warning. Other signals cover activity in each encrypted Hyper Backup repository on OK035, Watchtower's last check, Security Advisor results, and per-container image age with an update badge. Service tiles point at services reachable over Tailscale; Kibble uses its `kb-bnjx.tail4d7938.ts.net` hostname, while the other service tiles use the Tailscale IP (`100.126.55.95`).

## Rebuild

```sh
ssh ok040 'mkdir -p /volume1/docker/status-page'
ssh ok040 'cat > /volume1/docker/status-page/gather-status.py' < projects/status-page/gather-status.py
for f in index.html favicon.ico favicon.svg apple-touch-icon.png; do
  ssh ok040 "cat > /volume1/web/$f" < projects/status-page/web/$f
done
ssh ok040 'chmod 644 /volume1/web/index.html /volume1/web/favicon.* /volume1/web/apple-touch-icon.png'
```

The runtime mapping `/root/status-page-hyperbackup-cache-paths.json` is NAS-specific and is deliberately not in Git or the shared-folder backup. It contains no credentials and can be rebuilt by matching each encrypted task to its local cache directory. It must contain exactly the two expected labels, mapped to distinct cache paths under `/volume1/@img_bkp_cache/`. Keep it root-owned with mode `600`; `/root` is mode `700`. Provision this mapping before running the collector, or both backup rows will show `unknown`. If the NAS is rebuilt and the file is missing, the status rows will remain unknown until the mapping is recreated.

Then in Control Panel → Task Scheduler create a user-defined script task as `root` running `python3 /volume1/docker/status-page/gather-status.py`, and enable the Web Station default portal for `/volume1/web`. To run it by hand: `sudo env PATH=/usr/local/bin:$PATH python3 /volume1/docker/status-page/gather-status.py` (plain `sudo` lacks `docker` on its PATH and every container shows "unknown").

## How the signals are read

- **Time Machine**: mtime of `/volume1/timemachine/joost.sparsebundle`.
- **LinkedIn backup**: the newest directory under `/volume1/backup/linkedin-archive/` whose name is a UTC timestamp and which contains `MANIFEST.json` (the Mac job renames a backup into place only after verifying it, so an in-progress `.tmp-*` copy never counts). The Mac job runs hourly but only makes a backup when the newest is over 7 days old, so a healthy system stays under about 8 days. This is the independent check that the Mac job is still running: nothing on the Mac can report its own death.
- **Hetzner backup**: `last_success` and `ok` in `/volume1/backup/hetzner/status/last-run.json`, written by the nightly pull (see [hetzner-backup](../hetzner-backup/)). The owner reported in this conversation on 2026-11-15 that this row is deployed and green; `status.json` reports `hetzner_backup.status = ok`. This status was not independently live-verified for this update.
- **Encrypted backups to OK035**: newest top-level data-entry mtime in the local Hyper Backup cache dirs for Media (`Backup C`) and Time Machine Homes (`Backup D`), mapped by NAS runtime configuration at `/root/status-page-hyperbackup-cache-paths.json`. Empty caches are `unknown`, so a newly configured task is not marked healthy just from its directory creation time. The old unencrypted task caches are omitted because those schedules were disabled. This is a recency proxy, not a confirmed remote success; it catches "has not had local cache activity in over a week", not "ran and failed". Each row uses that repository's own age/status. The root-only mapping contains local paths, no credentials, and is not part of the volume backup; recreate it after a bare-metal rebuild.
- **Security Advisor**: `/var/lib/securityscan/securityscanResult.json`. Only `danger` and `risk` count as red; `info`, `warning`, `outOfDate` count as amber. Colour is the worse of scan age and findings.
- **Watchtower**: `docker inspect` for image age and `docker logs watchtower` for the last check and per-container flag. The per-container flag needs `WATCHTOWER_LOG_LEVEL=debug`. **Shows "unknown" since 2026-10-01**: Watchtower's log stopped receiving entries then and `docker logs watchtower` hangs (see [watchtower](../watchtower/)).
- **Container list**: discovered from `docker ps -a`, so new containers appear without editing the script. Containers outside Watchtower's list show a "manual" badge.

## Gotchas (kept from the original notes)

- `docker logs` only has output from the container's main process; `docker exec` output never appears there.
- Watchtower logs to stderr, so the script merges stderr into stdout.
- DSM's Python 3.8 `datetime.fromisoformat` rejects Docker's nanosecond timestamps; the script truncates first (`parse_docker_ts()`).
- Link tiles for qBittorrent and Prowlarr carry `rel="noopener noreferrer"` on purpose: qBittorrent's CSRF protection answers 401 when the Referer is another site or port.
- Favicon links carry `?v=2` to defeat browser caching; bump the number when the icons change.
- Compose changes for Watchtower and Immich need SSH, not the Container Manager UI.
- OK035 and Security Advisor: the one real finding on 2026-09-08 was that the built-in `admin` account is not disabled.
